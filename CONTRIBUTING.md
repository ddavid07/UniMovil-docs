# Contribuir a la documentación

1. Comprueba que el documento corresponde a este repositorio; la documentación técnica ligada al código pertenece a UniMovil.
2. Usa Markdown, enlaces relativos para archivos del mismo repositorio y títulos descriptivos.
3. Distingue hechos confirmados de propuestas y plantillas. No inventes fechas, asistentes, decisiones, resultados ni evidencias.
4. Para el trabajo de producto, sigue la [metodología Scrum](methodology/README.md); enlaza historias, decisiones y evidencias sin duplicar su contenido.
5. No incluyas secretos, credenciales, datos personales identificables ni información privada de terceros.
6. Mantén el contenido histórico señalado como histórico y no lo presentes como planificación vigente.
7. Abre una pull request breve, describe el motivo y revisa los enlaces y el diff.

Los cambios se revisan antes de incorporarse a main. No se exige instalar dependencias en local; el workflow valida el formato Markdown.
